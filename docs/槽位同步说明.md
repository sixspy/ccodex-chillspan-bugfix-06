# 槽位同步说明（BUGFIX-06 纪要 · 当班封死）

> 本文件是仓间槽位占用与批次入库同步口径的当班纪要，写入即生效。
> 任何偏离按 **“槽位偏航”拒写**。代码侧唯一事实源实现见 `backend/slots.py`。

## 一、缺陷定性

温控批次创建回执成功，但所属仓间在批槽位计数未抬一，调度屏仍示可再接批。
根因是新批事务漏同步抬占用，叠加仓间读口的视图环（`active - 1`）与
配额满放行（`if active >= quota: pass`）两处埋雷。

## 二、甲乙分叉择一，两边不得混用

- **甲路径（本仓唯一启用）——正式批次落库即同事务占槽**
  - `temp_batches` 正式行是槽位的唯一事实源；批次 INSERT 成功即占用抬一。
  - 配额复核 `slots.ensure_slot_available` 与 INSERT 在同一事务内，
    任一步失败整单回滚，绝不留半成品行。
  - 占用口径：`status NOT IN ('已封批','作废')` 的 `temp_batches` 行数。
- **乙路径（本仓未启用）——排产条影子副本**
  - 排产条可先落影子副本，正式占用零改；配额复核后原子并入，否则副本作废。
  - 本仓不允许影子行/半成品行落 `temp_batches`，也不允许用 `route_plans`
    排产条顶替正式占用（测试 `test_yi_no_shadow_no_sidewrite_on_reject` 钉死）。
- **禁止折中、禁止双写**：不另立可漂移的占用计数器。双写必然出现
  “批在表、槽位空”。
- **禁止只调色仓间视图环**：读口不得对事实值做 +/- 修饰，
  五处视图一律直读 `slots.count_active_slots`。

## 三、五视图同源

探头视图、对账视图、封批视图、批次视图、仓间视图的槽位数字全部来自
同一 SQL 口径（`backend/slots.py` 的 `count_active_slots`）：

| 视图 | 接口 | 字段 |
| --- | --- | --- |
| 仓间 | `GET /api/chambers/{id}` | `active_batch_count` / `quota_left` |
| 探头 | `GET /api/probes/{id}` | `active_batch_count` / `quota_left` |
| 对账 | `GET /api/reconcile[/{code}]` | `active_batches` / `quota_left` |
| 批次 | `GET /api/batches[/{id}]` | `chamber_active_batch_count` |
| 封批 | `GET /api/seals` | `chamber_active_batch_count` |

封批后批次状态转 `已封批`，COUNT 口径自动回落，五视图同步降一，无需双写。

## 四、并发占锁

两名调度同时向未满仓间提交建批，须串行占仓间锁（`chamber:{id}`）：

- 锁表 `chamber_locks` 与争用表 `contention_log` 走**独立自动提交连接**，
  与业务事务解耦：占锁立即全库可见，业务 409 回滚不带走锁行与争用痕。
- 占锁用 `INSERT ... SELECT ... WHERE NOT EXISTS`（无冲突语义），
  不用 `INSERT OR IGNORE`——后者在 WAL 并发下会走替换路径改写持有者。
- 后到争用只写 `contention_log` 痕，不插第二行业务行，返回 409。
- 数据库启用 WAL + `busy_timeout=30000`，并发写事务串行而非报库锁。
